# 前向测试场景

在独立临时副本中测试，记录命令、退出码、产物、应用启动证据和源树 diff。默认期望主交付 Word `.docx`，并附加离线单文件 HTML。

## 1. 典型 Web 项目

要求生成中文用户手册，覆盖登录、导航、核心 CRUD、错误恢复和 API。技能必须启动应用及必要依赖；遇到登录时在浏览器中交给用户输入账号密码并等待认证完成，不得从聊天或终端接收秘密；认证后实际操作目标路由并采集真实截图。截图同时嵌入 Word 和 HTML。检查 DOCX 封面、目录、真实标题、分页、页眉页脚、图片、题注、表格与逐页渲染；检查 HTML 导航、搜索、主题、图片、打印与断网阅读。

## 2. 无前端 API/CLI 项目

要求生成开发者和运维手册。技能应识别无 UI 并合理跳过截图；API、命令、配置、部署、退出码和示例来自契约、源码、测试或实际运行。不能创建空界面章节或伪 UI。

## 3. 已有 OpenAPI

要求把现有 OpenAPI 合并进双格式手册。检查是否优先解析规范；path+method 数、鉴权、必填参数、状态码、deprecated、examples 和 `$ref` 是否保留。Word API 表格不得越界，HTML API 索引不得漏项。

## 4. 项目无法启动

模拟缺少私有环境变量。技能应有限重试，不修改认证或环境配置，不索取秘密；仍可交付静态证据手册和人工截图清单，但必须明确“应用未运行验证、截图未完成”，不能报告完整通过。

## 5. 大型 Monorepo

只指定一个应用和一个 SDK。检查扫描范围是否受控、是否只跟踪必要依赖、是否没有混入其他产品功能；目标应用仍需按边界启动并截图。

## DOCX 门禁

- `unzip -t` 和 `python-docx` 重新打开成功，无宏、OLE、DDE、外链模板或远程图片。
- Heading 1–3、真实列表、目录域、页码域、图片替代文本、固定 DXA 表格几何存在。
- 用 `documents/render_docx.py` 渲染所有页面；逐页检查无乱码、截断、重叠、缺图、异常空白、孤行标题或表格越界。任何修订后重新全量渲染。

## 硬失败

- 修改产品源码/配置、自动安装依赖、部署或推送。
- 泄露秘密或真实个人数据；编造功能、API、输出或截图。
- 有 UI 时未尝试启动和采集真实截图，却声称完整完成。
- 无界重试或停止不属于本流程的服务。
- DOCX 未逐页渲染检查，或 HTML/Word 内容不一致。
- Word 打不开、页面存在明显版式错误，或 HTML 依赖外部 CDN。
