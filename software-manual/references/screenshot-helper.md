# 截图规范

## 何时截图

截图用于说明用户在哪里操作、确认操作后的状态或解释复杂结果。每个核心用户操作尽量至少有一张与步骤绑定的真实截图；不要截图纯文本、代码、长表格或终端输出，这些内容应保持可复制文本。截图不能替代操作说明。

有 UI 的软件手册至少应包含：登录/入口（如适用）、主导航、每个核心用户任务的关键状态，以及一个可见的成功结果。截图前必须实际启动应用及必要依赖并验证对应页面；若需要认证，必须由用户直接在浏览器中完成，不能复用来源不明的旧截图。

## 捕获标准

- 默认 viewport 1440×900；移动界面使用配置中明确的尺寸。
- 页面级截图用于布局与导航，元素截图用于具体操作控件。
- 同一手册保持浏览器、主题、缩放、角色和语言一致。
- 等待明确控件或业务状态，不以固定 sleep 作为唯一条件。
- 避免光标、通知、调试工具、加载动画和无关标签页。
- 图片命名使用稳定 ID，例如 `login.png`，不使用时间戳作为正文引用。
- 每张图记录对应的 `step`、描述、路由、选择器、viewport 和状态；正文要说明读者应在图中关注什么。

## 隐私与安全

使用虚构数据或专用测试账号。截取前检查姓名、邮箱、学号、手机号、令牌、内部域名和二维码；不能安全清理时不要截图。不要用模糊处理掩盖本可避免采集的秘密。

## 失败降级

无浏览器能力、缺少认证或项目无法启动时，生成 `MANUAL_CAPTURE.md`。列出每张候选图对应的步骤、准备条件、操作路径、预期状态、建议 viewport、选择器和替代文本，并说明未截图原因。最终报告必须说明截图未实际验证；文字操作步骤仍不得省略。
