# 阶段 3.5：整合

## 检查顺序

1. 读取全部章节及子智能体返回摘要。
2. 对照 `manual-config.json` 和 `evidence-map.json` 检查覆盖。
3. 统一产品名、版本、角色、菜单名、配置键和术语。
4. 删除重复内容，把共享步骤放到唯一位置并建立交叉引用。
5. 检查标题层级、代码语言、表格、链接、截图标记和示例占位值。
6. 提取截图标记为 `screenshots-list.json`，确认每张图有 `step`、描述、题注语义和正文引用位置；每个核心操作至少有一张截图，未截图步骤记录原因。
7. 写 `manual-outline.json`，记录章节顺序、标题层级、分页建议、图表标题和交叉引用。
8. 写 `consolidation-summary.md`，列出已修复问题、剩余缺口和证据冲突。

## 硬门禁

以下任一存在时暂停组装并先修复：

- 虚构或互相冲突的功能事实。
- 关键任务缺少前置条件、结果或恢复路径。
- 真实秘密、令牌、个人数据或内部敏感地址。
- 无法解释的版本混用。
- 截图标记缺少唯一 ID 或描述。

“截图尚未采集”可以作为后续阶段的已知缺口，不等同于内容错误。
