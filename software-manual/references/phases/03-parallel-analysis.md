# 阶段 3：并行分析与撰写

## 章节选择

按用户需要和项目能力选择，不固定六章：

- 产品概述、系统要求、安装与快速入门。
- 界面和核心用户任务。
- CLI、API、SDK 或扩展参考。
- 配置、部署、运维和安全边界。
- 故障排查、错误码和恢复步骤。
- 入门、进阶与高级示例。

无 UI 时不生成界面章节；无公共 API 时不生成空参考；最终用户手册不塞入无关内部架构。

## 子智能体任务模板

```text
[范围] 只负责 <章节>，不得修改产品源码或共享配置。
[输入] manual-config.json、evidence-map.json、明确列出的源码/测试/API 资料。
[输出] <work-dir>/sections/<unique-file>.md。
[要求] 每条功能事实有证据；未验证项进入 gaps；步骤包含前置条件、动作、预期结果和失败恢复；标题只使用 1–3 级；截图位置使用标准标记并包含可读 description。
[返回] status、output_file、evidence_count、coverage、gaps、warnings。
```

主 Agent 不把大段章节内容回传到上下文；只收路径与摘要。子智能体不得同时修改同一文件。

## 章节内部结构

任务式章节建议使用：

1. 目标。
2. 前置条件与权限。
3. 操作步骤。
4. 预期结果。
5. 常见失败与恢复。
6. 相关参考。

API/配置参考建议使用：用途、签名或键、类型、必填性、默认值、约束、示例、错误/安全注意事项。

## 截图标记

仅在截图能帮助定位或确认状态时添加。一个标记对应一个明确状态；不要用截图承载代码、长文本或唯一信息。

Markdown 是 Word 组装前的内容中间格式，不是默认交付物。避免用原始 HTML 实现正文布局；表格只承载真正的行列数据。
