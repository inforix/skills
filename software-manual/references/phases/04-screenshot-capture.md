# 阶段 4：截图捕获

## 决策

当 `has_ui=true` 时，本阶段默认必做：先按 [运行与认证流程](../runtime-and-auth.md) 启动应用及必要依赖，必要时让用户在浏览器中人工认证，再验证业务路由并采集真实截图。只有用户明确禁止运行、依赖/认证确实缺失或应用无法安全启动时才能降级。能力顺序：Codex 浏览器控制工具 → 项目已有 Playwright 环境 → 人工截图清单（部分完成）。

## 运行边界

- 使用仓库已有启动命令和依赖，不执行安装或迁移；相关依赖组件也必须按运行拓扑先后启动并验证就绪。
- 启动前检查端口占用；记录新进程 PID。
- 不接管或停止已有服务。
- 私有环境变量缺失时停止运行尝试，转为静态文档和人工截图清单。
- 同一启动或页面问题修正后最多再试两次；不要无限等待。
- 不为截图修改 `.env`、认证逻辑、种子数据、依赖锁文件或产品源码。

## 捕获流程

1. 准备无敏感信息的测试状态和必要角色。
2. 启动应用及必要依赖，并记录命令、PID、监听地址、启动日志与就绪证据。
3. 打开目标路由；若出现认证页面，暂停让用户直接在浏览器中完成认证，不代填或接收秘密。
4. 用户完成认证后，验证已登录的业务状态，再完成到标记所需的页面状态。
5. 等待稳定元素可见、网络活动结束或明确的业务就绪信号。
6. 验证页面不是登录重定向、空态、错误页或骨架屏；HTTP 200 本身不算业务验证。
7. 使用一致 viewport 捕获页面或最小必要元素。
8. 保存 PNG/JPEG 并记录 route、selector、viewport、时间、描述和验证状态。
9. 只停止本流程启动的进程。

## 输出

成功时写 `screenshots/screenshots-manifest.json`，并把截图同时嵌入 Word 与单文件 HTML。失败时写 `screenshots/MANUAL_CAPTURE.md`，逐张列出路由、前置状态、选择器、描述和敏感信息清理要求；有 UI 但没有真实截图时，整项交付只能标记为部分完成。
